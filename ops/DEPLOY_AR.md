# تشغيل Linux وبيئة اختبار HTTPS/PostgreSQL

**قالب نشر أُعد ولم يُنفذ هنا. لا يوصف النشر أو PostgreSQL بأنه ناجح حتى يختبر على المضيف الفعلي.**

## 1. المحلي

`sh Start-Linux.sh` يستخدم SQLite على loopback. المتطلبات مثبتة بما استُخدم محليًا، وليست ادعاء بأن كل الإصدارات أحدث إصدار أو خالية من ثغرات. افحص التبعيات والصور يوم النشر. توافر Python وvenv والإنترنت أول مرة مطلوب. سكربت البداية لا يثبّت النظام أو Docker نيابة عنك.

## 2. مسار الحاويات المعزول للتجربة

الملفات: `compose.yaml` وDockerfile وCaddyfile و`.env.example`. الخدمات: تطبيق واحد + PostgreSQL + وكيل TLS. لا توجد عدة عقد أو HA أو نسخ احتياطي آلي. منفذ PostgreSQL غير مكشوف للمضيف في القالب.

يتطلب نطاقًا مملوكًا يشير إلى عنوان Linux، واتصال تنزيل الصور والحزم، وDocker مع Compose، وإتاحة المنفذين 80 و443 لإصدار الشهادة. لا تستخدم example.com فعليًا.

```sh
cp .env.example .env
chmod 600 .env
openssl rand -hex 32
# ضع قيمة التوليد في POSTGRES_PASSWORD، ونطاقك في DOMAIN باستخدام محرر آمن.
docker compose config --quiet
docker compose up --build -d
docker compose ps
docker compose logs --tail=80 app
```

لا تُرفق مخرجات `docker compose config` الكاملة أو السجلات المحتوية أسرارًا في رسائل عامة. إعداد DATABASE_URL داخل Compose يستخدم كلمة مرور hex لتجنب تعقيدات ترميز URI. `.env` لا يُحفظ في مستودع Git.

ملف الحسابات يُقرأ بواسطة المشغل فقط:

```sh
docker compose exec app cat /app/data/first-run-accounts.json
```

عند نجاح التشغيل اختبر `/api/health`: ينبغي أن يذكر `postgresql` لا `sqlite`. حقل `native_postgres_tested_here:false` يصف بيئة إعداد هذه الحزمة، وليس نتيجة قبول مضيفك. سجّل نتيجة اختبار المضيف وتاريخه منفصلًا. اجعل كلمة مرور كل حساب جديدة قبل تسليم المستخدمين، ولا تعرض ملف الحسابات في اجتماع أو رابط عام.

## 3. HTTPS وQR والأجهزة

`PUBLIC_ORIGIN` يجب أن يطابق العنوان النهائي، بما في ذلك البروتوكول والمنفذ إن وجد. منه يولد QR. QR لـ127.0.0.1 لا يصل إلى الخادم من هاتف آخر. تجنب اسم نطاق جديد بعد تجهيز التابلت: التخزين مرتبط بأصل الموقع.

اختبر من هاتف خارج شبكة الخادم، ومن هاتف داخل المعرض. جهّز التابلت عبر زر «التجهيز دون إنترنت» في نفس العنوان HTTPS. افتح الصفحات فعليًا بعد التحميل ثم افصل الاتصال؛ نجاح استجابة HTTP لا يكفي لإثبات عمل Service Worker.

## 4. التخزين والنسخ الاحتياطي

لا تستخدم `docker compose down -v` على بيئة تحتوي بيانات مطلوبة: يحذف الأحجام. لا تحذف مجلد `data/` على التشغيل المحلي.

نسخة PostgreSQL تجريبية منطقية:

```sh
umask 077
mkdir -p backups
stamp=$(date -u +%Y%m%dT%H%M%SZ)
docker compose exec -T postgres pg_dump -U pulsex -d pulsex -Fc > "backups/pulsex-$stamp.dump"
# انسخ أيضًا وسائط volume التطبيق بإجراء النسخ الخاص بمضيفك.
```

لا يكفي وجود dump. يجب استعادته في قاعدة اختبار منفصلة، ومطابقة نسخ الصفحات وعدد المشاركات والوسائط. لا تُجرب استعادة مدمرة على قاعدة التشغيل. النسخ المتقدمة وPITR وسياسة التشفير والاحتفاظ غير معتمدة بهذه الحزمة.

## 5. فحوص إلزامية قبل جمهور حقيقي

هوية وصلاحيات عبر المتصفح، حدات بيانات وإيصالات وعدم تكرار على PostgreSQL، استيراد ونشر، رفض وصول جهة لجهة أخرى، رفض origins غير المخولة، صور وفيديوهات، إدارة جلسة التاب، استعادة نسخة احتياطية، إزالة الحسابات/المحتوى الوهمي أو تمييزه، موافقة صاحب البيانات، واختبار الجهازين. لا يوجد اختبار اختراق أو مراجعة أمن مستقلة في التسليم.

مستخدم التطبيق يملك مخطط التجربة؛ العزل في التحقق الخادمي وليس RLS مكتملًا. مدير المنظم مخول داخل معرضه. مكافحة الإساءة تحديد معدل أولي داخل عملية واحدة، وليست بوابة موزعة أو منع تزوير هويات المتصفح. لا تستخدم هذه النسخة في تصويت رسمي أو جوائز حساسة أو جمع معلومات شخصية حساسة.
