# استقلال النظام وإدارة نسخ الأصول

قرار المستخدم في 31 أكتوبر 2026: يملك كل نظام نسخته من المكونات المشتركة
ويطوّرها ويصدرها بصورة مستقلة. الأصل المشترك مصدر اختياري للترقيات المراجعة.
لا تُضاف تبعية تشغيلية على Smart Engineering أو مستودع تطوير آخر.

## التشغيل المحلي

```sh
python3 -m unittest discover -s tools/asset-control -p 'test_*.py'
python3 tools/asset-control/asset_control.py verify
```

الأداة مكتبة Python القياسية فقط، ولا تتصل بالشبكة أو تحمل المصدر أو تشغّل
أوامر من ملفات الإعدادات. تفحص بصمات الأصول المسجلة ووجود Git submodules.
حالة registration-required ليست نجاحًا؛ يلزم تسجيل الأصول الناقصة.

## نسخ أصل جديد

جهّز تصديرًا محليًا مراجعًا من إصدار ثابت دون أسرار أو حزم مبنية، ثم:

```sh
python3 tools/asset-control/asset_control.py adopt --source /path/to/reviewed-export --destination vendor/component --id component.name --origin owner/repository --revision FULL_40_CHARACTER_COMMIT --version 1.0.0
```

تُنسخ الملفات الفعلية ويُسجل المصدر والإصدار والبصمات. ترفض الأداة المسارات
الخارجة والروابط الرمزية واستبدال نسخة موجودة. تحتاج الترقية إلى مقارنة
التعديلات المحلية مع الإصدار الأصلي والجديد، واختبارها، وتحديث القفل في تغيير
مراجع. يمكن تطوير النسخة محليًا؛ حدّث إصدارها والبصمات بعد مراجعة فرق Git،
واحتفظ بمصدرها الأصلي وسجل تغييراتها. لا يوجد تحديث تلقائي أو كتابة مركزية.

## نطاق الإثبات

assets.lock.json يسجل مكونات محلية مرصودة عند Commit محدد، وليس جردًا
مكتملًا لكل تبعيات النظام. origin=self يعني تثبيت خط الأساس المحلي، ولا يدّعي
معرفة مصدر أقدم غير موثق. لا تُعد المسارات التاريخية أو المستوردة نشطة تلقائيًا.
لكل رحلة قبول مستقلة للبناء والتخزين والهوية والعزل والواجهة وفشل الطرف الخارجي.
انقطاع API أعمال خارجي لا يبرر تكرار الأرصدة أو تجاوز الصلاحيات أو نجاحًا وهميًا.
