# قرار العرض ورسائل الحضور — المرحلة 06

مصدر تفاصيل الفعالية للزائر هو نسختها المنشورة فقط، وليس مسودة الإدارة. الأيام والصلاحيات تؤخذ من سياسة الحضور والدعوة؛ زمن الهاتف لا يمد الاستحقاق. لم يفرض هذا التغيير قيدًا جديدًا يربط كل يوم دعوة بحدود start/end، إذ لا يوجد قرار منتج يجيز إسقاط يوم أو موافقة بسبب جدول العرض العام.

تعرض الواجهة «بداية الجدول العام المنشور» و«نهاية الجدول العام المنشور» مع توقيت الفعالية، وتوضح استقلاله عن أيام صلاحية الدعوة. إذا اختلفا، يراجع الزائر المنظم؛ لا تُعرض مسودة سرية لإخفاء التعارض ولا تعدّل الأيام أو الحجوزات تلقائيًا.

عند إنشاء demo جديدة فقط، يبدأ نموذجها في يوم الإنشاء بتوقيت عدن ويمتد خمسة أيام، وتتحرك الجلسة ومشاركة الجهات مع الجدول نفسه. يمكن الاختبار بساعة/يوم محكوم. إعادة seed على قاعدة قائمة لا تحدث البيانات أو النسخة المنشورة؛ تعديل فعالية قائمة يمر عبر مراجعة ونشر المنظم المعتادين.

| الحالة | معنى الرسالة والإجراء |
|---|---|
| pending_approval | استلم الرد، لكنه بانتظار مراجعة المنظم؛ لا QR معتمدة |
| approved | اعتمدت الدعوة؛ هذا لا يعني تسجيل الدخول، إذ يلزم تأكيد الخادم عند المسح |
| revoked / rejected / expired | لا بطاقة قابلة للاستخدام في الواجهة؛ التواصل مع المنظم |
| unknown-outcome | لا نجاح نهائي؛ إعادة نفس العملية والكمية للتحقق، مع حفظ scan_id |
| unmanaged offline | حركة محلية مؤقتة إلى أن يصل receipt الخادم |
| managed offline | لا قبول دخول دون الخادم؛ المخبأ ليس سلطة للسعة |
| counter stale | القيم قديمة مع آخر وقت تحديث وزر إعادة تحديث؛ لا يلغى نجاح POST مؤكد |

inside_count عدد التذاكر بحالة inside، وليس إشغال أفراد المجموعات. admitted_people مجموع الكميات المستهلكة، وقد يشمل الشخص عبر أيام مختلفة. total_checkins عدد الحركات الكلي؛ لا يستنتج من نافذة آخر 500 حركة.

الأوقات العامة تحتاج offset أو Z، وتعرض بالمنطقة الخاصة بالفعالية. الموعد غير الصالح أو الناقص لا يتحول إلى Invalid Date، ولا يُفسر كتوقيت جهاز الزائر. الأيام تعامل كأيام تقويمية، ولا تتحرك بتحويل منتصف الليل المحلي إلى منطقة أخرى. اختبارات JS تثبت تكافؤ UTC و+03:00 وحدود اليوم، بينما فحص الهاتف 390px والطباعة وQR الحقيقي يحتاج Chromium ثم العتاد.

رفعت shell إلى v26 لتغير محتوى الأصول. بقيت API خارج precache، وجميع أصول القائمة تفحص عبر HTTP/MIME. لم يُختبر انتقال Service Worker حي من v25 إلى v26 في متصفح هنا؛ فحص الأصول لا يثبت هذا الانتقال أو جودة الطابعة.
