## عقد الطلب واللوحة

`idle → sending → confirmed/rejected`، أو `unknown-outcome` عند فقد الرد أو HTTP غير ناجح أو عقد غير معروف. تبقى scan_id وquantity معزولتين بمفتاح event+pass. فشل تخزين pending قبل الإرسال يمنع POST؛ تلفها يمنع إنشاء معرف بديل. أخطاء 401/403 تعرض طلب إعادة المصادقة، و409 يحتفظ بالهوية أيضًا؛ لا يُستنتج rollback من رقم الحالة بعد محاولة سابقة مجهولة.

| رد API | مصير pending |
|---|---|
| accepted / duplicate | confirmed ثم محاولة تنظيف التخزين؛ فشل التنظيف لا يغير النجاح |
| already_inside / already_outside / invalid / rejected في رد ناجح | rejected وتنظيف pending |
| HTTP 401/403 | unknown-outcome؛ توقف وإعادة مصادقة، والهوية محفوظة |
| HTTP 409 أو أي 4xx/5xx أو timeout | unknown-outcome؛ إعادة بنفس الهوية والكمية |
| رد ناجح بحالة غير معروفة | الاحتفاظ بالهوية ورسالة تحقق؛ لا نجاح كاذب |

sessionStorage تخص التبويب. لا يُدّعى منع تكرار هوية عميلة عبر متصفحات مختلفة؛ الخادم يحكم السعة. لا توجد إعادة POST آلية في Caddy. حالة اللوحة مستقلة current/stale مع نص مرئي وآخر وقت تحديث وزر تحديث يدوي. طلب in-flight واحد يمنع الردود المتداخلة. بعد unmount تُهمل النتيجة ويتوقف المؤقت؛ الطلب الجاري ينتهي بمهلة api الحالية، وهي 12 ثانية.
