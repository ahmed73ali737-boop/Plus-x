# المرحلة 01 — خط الأساس وحواجز الجودة وإعادة البناء

تُنفذ هذه المرحلة فوق `f53c206c0d113e6db9c11afab7569fbe868b5dd7`، استنادًا إلى ملفي الخطة المرفقين بتاريخ 20 أكتوبر 2026. هوية المرشح النهائي تؤخذ من `git HEAD` أثناء التشغيل، وليست رقمًا يدويًا داخل الوثيقة. لا تعد هذه المرحلة قبولًا للإنتاج أو تعافي الوكيل أو نقل البطاقات أو العتاد الميداني.

## قرار المصدر وحدود R01

الخطة تشير إلى خمسة اختبارات معدلة وملف انحدار جديد على جهاز Windows. محتوى هذه الملفات غير مرفق. جرى جرد نسخة العمل الحالية ونسختين محليتين أقدم؛ التعديلات المتاحة في النسخ القديمة تطابق commits سابقة مدمجة بالفعل في خط الأساس. لا يوجد دليل يربطها بتعديلات دورة 20 أكتوبر.

لذلك **استرداد تلك الملفات الستة ما زال محجوبًا لعدم توفر محتواها**. لم تُحذف أو تُستبدل تعديلات المستخدم على جهازه. لا تنسب أرقام Windows160 وLinux158 إلى هذا المرشح. غلاف `tests/test_invitations_ui_contract.py` اختبار جديد مستقل، وليس استعادة للملف المفقود. القرار القابل للقراءة الآلية في `ops/phase01-baseline.json`.

## EOL والأقفال

- تظل خوارزميتا SHA256 وGit blob SHA1 مستقلتين وتقرآن البايتات الفعلية. لا تغيير لبصماتهما أو لملفات الترحيل 002–009.
- قاعدة LF الخاصة بـ`requirements-observability.txt` موجودة في خط الأساس. أضيفت قواعد LF محددة لمدخلات الاعتماديات وأقفالها الجديدة حتى لا تتبدل بصمات إعادة البناء بين Windows وLinux.
- تظل `cmd` و`ps1` بنهايات CRLF المقصودة، ولا يوجد reset أو renormalize شامل.
- تفحص أداة التشخيص working tree والفهرس وHEAD وGit attributes. الحالات السلبية تعدل نسخًا مؤقتة فقط: تغيير نص فعلي وCRLF عرضي؛ يجب أن يرفضهما كل حارس ثم يقبل استعادة البايتات الأصلية.
- محاكاة سياسة checkout الخاصة بـWindows على Linux ليست تنفيذًا على Windows. فحص Windows الأصلي في CI دليل مستقل.

## عقود الدعوات وهوية الأدلة

يُشغّل pytest عقد `invitations_ui_contract.mjs` الحقيقي بواسطة Node. غياب Node أو خروجه بفشل أو غياب تقرير صالح يفشل الاختبار؛ التقارير الخضراء المطبوعة لا تتجاوز exit code غير صفري. الحالات السلبية تشغّل pytest فرعيًا يفشل عمدًا، وتحفظ JUnit والسجل دون احتسابها رحلات متصفح حقيقية.

كل وظيفة CI تبدأ بـcheckout لمرجع PR الفعلي أو SHA الدفع، ثم snapshot. تُسجل بصمات ملفات المصدر والاختبارات ونسخ Python وNode والحزم. تلتقط وظائف المتصفح وPostgreSQL نسخ محركاتها عند ختم الأدلة. يقارن الختم بايتات المصدر بلقطة البداية، ويحسب SHA256 للأدلة المنسوخة إلى الحزمة.

بوابة التغليف تتحقق من SHA وtree وrun ID وrun attempt واسم الوظيفة وسلامة بصمات الأدلة ونتائج تقارير القبول. لا تقبل نجاحًا من تشغيل أقدم أو وظيفة فاشلة أو تقريرًا محجوبًا. ملفات `qa` و`dist` مخرجات مولدة وليست مصدرًا ثابتًا؛ تنظف الوظائف ملفات القبول المطلوبة تنظيفًا محددًا قبل تشغيلها حتى لا تمر أدلة تاريخية ملتزم بها.

تُحفظ أدلة الفشل بواسطة `if: always()`، دون `continue-on-error`. تقارير JUnit التي تشير إلى فشل أو خطأ مرفوضة. الاستثناء المنصّي الوحيد هو اختبار صلاحيات POSIX عند التشغيل على Windows؛ يسجل بوصفه مستبعدًا ولا يضاف إلى عدد الاختبارات الناجحة. عقود الدعوات المطلوبة لا تسمح بـskip.

## الاعتماديات والصور

تُفصل ملفات runtime وpostgres وqa وqa-postgres وobservability، مع تثبيت الاعتماديات المتعدية وبصمات توزيعاتها في `requirements/locks/`. لا تدخل Playwright وحزم QA إلى صورة الإنتاج. تبقى ملفات المتطلبات الأصلية مدخلات معلنة، ويصبح التثبيت المعتاد من الأقفال مع التحقق من hashes.

تثبت صور Python وPostgreSQL وCaddy باستخدام OCI manifest digests المسجلة في `ops/container-image-lock.json`. لا يشترط تطابق digest صورة ARM64 مع x86_64؛ المطلوب منشأ ثابت وعقود متطابقة. تثبيت الصورة لا يلغي الحاجة إلى تحديث أمني مقصود لاحقًا.

أداة `tools/verify_reproducible_runtime.py` تنشئ بيئتين افتراضيتين منفصلتين وتقارن الحزم المحلولة بعد التحقق من القيود. يظل `tzdata` مثبتًا، ويُختبر `Asia/Aden` مع تعطيل ملفات المناطق الزمنية في النظام. تنفذ CI إعادة البناء على Python3.12/Linux وPython3.13/Windows، مع تحقق ARM64 في وظيفته الأصلية.
