## نتيجة المرشح المحلية

على `d533e222bf56899c0d1145c89a06a3b321914e44`: نجحت **252 حالة pytest** (يشغّل بعضها عقود Node وHTTP فعلية)، و**13 فحص أمان**، و**1000 ضيف** مع إعادة 100 عملية، و**700 قراءة لـ70 جهة بـ20 عميلًا** دون أخطاء، ثم **1000 قراءة و1000 إدخال** مع تطابق 1000 صف محفوظ. لا تجمع هذه العدادات كنسبة جاهزية؛ طبقاتها وأغراضها مختلفة.

فشل الجمع الأول عند حساس الموارد قبل pilot، ثم نجحت الإعادة مع `available=false` للرصد المتعذر. السجلان محفوظان. نتائج الأداء لا تشمل قبول SLO أو PostgreSQL أو العتاد.

## الأدلة

- [تقرير المرشح المتكامل](evidence/phases05-08/integrated-2/candidate.json): الأوامر ورموز الخروج والبيئة وبصمات المصدر والأدلة. `local_status` يصف المتاح هنا؛ `status=blocked` يمنع خلطه بقبول الإصدار.
- [الفشل الأول للجمع](evidence/phases05-08/integrated/candidate.json): فشل حساس psutil قبل بدء pilot محفوظ، ولا يُمحى بنجاح الإعادة.
- [manifest قبل الإصلاح](evidence/phases05-08/manifest-before.log) و[بعده](evidence/phases05-08/manifest-after.log).
- [ميزانية SQL قبل الإصلاح](evidence/phases05-08/query-budget-before.log) و[بعده](evidence/phases05-08/query-budget-after.log): 144 مقابل 5 SELECT للمدخل نفسه. لا تغيير لأقفال سلامة الكتابة أو المخطط.
- [pip-audit لبيئة QA](evidence/phases05-08/audit-qa.json): 55 اعتمادًا مثبتًا، صفر ثغرات معروفة في نتيجة الفحص المحفوظة. لا يساوي pentest. مطابقة [أقفال runtime](evidence/phases05-08/runtime-audit-coverage.json) أثبتت أن الحزم الـ19 المطلوبة لهذه البيئة مشمولة بالإصدارات نفسها في فحص QA، بلا نقص أو اختلاف. هذا استنتاج تغطية من النتيجة نفسها، وليس استعلام ثغرات جديدًا أو قبولًا لـWindows/ARM64. بقي فحص runtime المستقل [المحجوب بمهلة الشبكة](evidence/phases05-08/audit-runtime.log).
- [بروفة PostgreSQL](evidence/phases05-08/upgrade-rehearsal.json): blocked بلا اتصال اختبار وأدوات. ملف workflow جديد ليس نجاح تشغيل.
- [مصفوفة القبول](ACCEPTANCE_MATRIX_PHASES05_08_AR.md) تربط السيناريو بالاختبار والقرار، و[سجل المشكلات](acceptance-register.json) يميز verified محليًا عن accepted.

انخفاض الاستعلامات موثق، وكذلك نجاح حمل القراءة بعده. أزمنة القياس لا تعتمد SLO غير موجودة؛ اختلاف أزمنة الإعادات يعكس البيئة والجدولة ولا يؤسس مقارنة عتاد أو شهادة إنتاج. قياس الموارد إن جاء available=false يبقى محجوبًا ولا يستبدل بصفر.

## التشغيل والبيانات

راجع [دليل الترقية والبطاقات](UPGRADE_PASSES_OFFLINE_RUNBOOK_AR.md) و[قرار العرض والمصطلحات](EVENT_PRESENTATION_DECISION_AR.md) و[دليل الاختبارات](../tests/README_AR.md). لم يتغير schema أو SQL التاريخي أو قيود السعة أو الأدوار. لا تزال بيانات الجمهور خارج اختبارات الأعطال وreset.

فحص PostgreSQL الجديد ينشئ قاعدتين عشوائيتين فقط ببادئة px_rehearsal_، ويرفض العمل دون إعلان بيئة الاختبار. لا يُستعاد dump فوق بيانات تشغيل. SQLite backup خاص بها وحدها؛ الاستعادة بعد كتابة حركات جديدة تتطلب مصالحة تحمي ledger.

| قارئ/كاميرا/طابعة وهواتف وشبكة قاعة | blocked | أجهزة معلومة وتجربة انقطاع وعودة، وتوقيع المنظم على النمط المقبول |

لا تُحدّث FINAL_RELEASE إلى verified ولا تُعيّن أعلام الإنتاج قبل إغلاق الأدلة اللازمة. بوابة الإفراج أصبحت ترفض المصدر القديم والملفات المفقودة أو المخالفة والنتائج المصنفة fixture والبيئات غير المحددة؛ لا تستطيع بصمة ملف وحدها توثيق حقيقة تجربة ميدانية.

## محضر الميدان المطلوب

يراجع المسؤول نسخة [قالب القبول المحجوب](acceptance-manifest.example.json)، ويسجل SHA والحزمة والصورة والنظام والمعمارية والقاعدة والمتصفح وأسماء الأجهزة وأوقات الاختبار والأدلة وبصماتها. يختبر هاتفين وبوابتين وإبطال بطاقة ونهاية مناوبة وقائمة بوابات فارغة وانقطاع الشبكة وعودتها وACK مفقودًا وعدادات متعذرة.

الدعوة المدارة ترفض الدخول دون الخادم. غير المدارة تحفظ حركة مؤقتة ثم تقارن receipt والledger بعد العودة. لا تستنتج خمسة أيام offline أو عمل طابعة أو قارئ أو مزود خارجي من تشغيل محلي. الحقول الغائبة تبقى blocked، ولا تحول إلى pass بالافتراض.
