# دليل الترقية والبطاقات والعمل دون اتصال — المراحل 05 و07

هذا دليل تشغيل مرشح واختبار معزول؛ ليس تصريحًا لنقل بيانات حقيقية أو قبولًا للاستعادة الإنتاجية. ملفات SQL التاريخية 002–009 وبصماتها لم تتغير.

## القرار التنفيذي

تبقى الفعاليات ذات التسجيلات القديمة على نمطها غير المُدار إلى أن توجد خطة تحويل صريحة لكل فعالية. تظل `LEGACY_PASSES_REQUIRE_MIGRATION` مانعًا لتفعيل الدعوات فوق تسجيلات لا ترتبط بدعوة صحيحة. لا تُحقن `invitation_id` في metadata، ولا يُحوّل الهاتف وحده إلى وسيلة استعادة بطاقة.

أداة الجرد لا تملك وضع apply. لا توجد أداة تحويل عامة في هذا التسليم؛ صنع موافقات واستحقاقات تلقائية كان سيتجاوز قرار المنظم والسعة والأيام. إنشاء فعالية مدارة جديدة أو تصميم تحويل مراجع خياران لاحقان يحددهما صاحب البيانات.

## مصفوفة التوافق

| الطبقة | قبل 008 | بعد 008/009 | شرط التبديل |
|---|---|---|---|
| هوية الشخص الداخلية | guest_id ثابت | ثابت | الحركات تبقى مرتبطة به |
| البطاقة العامة | قد تكون مشتركة أو قديمة | G- مع 30 محرف hex، خاصة بالفعالية | رفض القديمة دون alias؛ إعادة توزيع مخولة |
| manifest | قديمة أو credential_version=1 | credential_version=2 | تطابق الفعالية والجهاز والعمر والمناوبة |
| shell | px-shell-v25 | px-shell-v26 | تنزيل الأصول الجديدة وتنشيطها قبل فتح البوابات |
| الدعوة المدارة | غير متاحة أو غير مربوطة | موافقة واستحقاق وسعة مشتركة | يتطلب المسح تأكيد الخادم |
| الفعالية غير المدارة | سياسة مستقلة | ما زالت مستقلة | الحفظ المحلي مؤقت حتى receipt مؤكدة |

## الجرد قبل أي نقل

في بيئة مصرح بقراءتها، يحدد المشغل `DATABASE_URL` دون طباعته في سجل أو ملف عام، ثم يشغّل:

```sh
python -m tools.upgrade_inventory --output private-qa/upgrade-inventory.json
```

الجرد يستخدم معاملات قراءة فقط على PostgreSQL وquery_only على SQLite. يُحصي الجداول والتسجيلات والبطاقات القديمة والروابط الصحيحة وغير الصحيحة بالدعوات وقيود الأجهزة والترحيلات المفقودة أو المخالفة. لا يطبع أرقام هاتف أو بطاقات أو token hashes.

الجرد لا يعلم ما طُبع أو وُزّع ولا حالة متصفح معزول. يلزم سجل خاص لدى المنظم، لكل فعالية: عدد البطاقات الموزعة، الجهة المخولة بإعادة تسليمها، الأجهزة ومناوباتها ونقاطها، وقت آخر manifest وإصدار shell، والأيام والسعات والموافقات والاستهلاك. لا توضع روابط بطاقات حقيقية في التقرير العام.

## البروفة القابلة للتكرار

على قاعدة اختبار مخصصة فقط:

```sh
python tests/postgres_upgrade_rehearsal.py
```

تتطلب `PX_POSTGRES_TEST_URL` و`PX_ALLOW_POSTGRES_TEST_RESET=YES` وأدوات PostgreSQL المتوافقة. يمكن أن تحدد CI حاوية الاختبار عبر `PX_POSTGRES_CONTAINER` لاستخدام pg_dump/pg_restore من الصورة نفسها. أسماء قاعدتي البروفة مولدة ببادئة `px_rehearsal_`، ولا يُستعاد dump فوق القاعدة المحددة في الاتصال أو قاعدة قائمة.

البروفة تنشئ مخططًا قبل 008 وبيانات اصطناعية وحركة تاريخية، ثم تتحقق من:

1. تطبيق 008/009 وبقية سلسلة الترحيل ذات الثماني بصمات.
2. بقاء الضيف والحركة وعلاقات التسجيل، ورفض البطاقة القديمة وصحة الجديدة.
3. إعادة المشغل دون تدوير جديد أو أثر إضافي.
4. فشل SQL مصطنع في ملف اختبار مؤقت وتراجع DDL وعدم تسجيل نجاح جزئي؛ التاريخ لا يعدل.
5. استمرار منع تحويل legacy إلى managed بلا خطة.
6. dump ثم restore إلى قاعدة أخرى ومطابقة بصمات كل جداول px_.
7. اكتشاف حركة لاحقة للنسخة وعدم استعادة نسخة قديمة فوقها.

الاختبار الحالي محجوب هنا لغياب PostgreSQL وأدواته. تعريف workflow ليس نتيجة تنفيذ. بروفة SQLite المحلية اختبرت الاستعادة والحركة اللاحقة والوسائط الاصطناعية، ولا تعوض PostgreSQL أو PITR.

## نافذة التبديل

- يحدد صاحب التشغيل نافذة تتوقف خلالها كتابات الأجهزة والاستقبال والإدارة. لا تفترض وجود وضع صيانة داخل التطبيق، ولا تطفئ سياسة الدعوات لتجاوز المنع.
- يؤخذ backup متسق للقاعدة والوسائط مع تأمين الوصول إليه؛ تُجرب الاستعادة قبل الاعتماد عليه. `backup_local` خاص بـSQLite ويرفض PostgreSQL.
- تراجع نسخة الكود والمخطط والبصمات والجرد، ثم تنفذ الترقية المعتمدة. فشل الترحيل يمنع الجاهزية؛ لا تغيّر checksum لتجبر التشغيل.
- يعيد المنظم توزيع البطاقات الجديدة عبر قناة متحقق منها. الهاتف وحده لا يثبت حق حامل البطاقة.
- تحدّث جميع الأجهزة إلى shell v26 وmanifest v2. تفحص فعالية صحيحة وأخرى مختلفة، وبطاقة قديمة وأخرى مبطلة، ونهاية مناوبة، وقائمة checkpoints فارغة.
- لا تفتح البوابات قبل تأكيد الأجهزة والسياسة والاتصال المطلوب. التصاريح المدارة لا تقبل من مخبأ عند انقطاع الخادم، حتى لو فتحت PWA.

## التراجع وحماية ledger

قبل أي كتابة جديدة يمكن النظر في الاستعادة المعزولة المجربة بعد التحقق من توافق نسخة الكود والمخطط والبطاقات. بعد كتابة حركة جديدة، لا تعاد snapshot قديمة تلقائيًا؛ إنها تفقد الاستهلاك وتعيد فتح حصة مصروفة. يحصى الفرق وتجرى مصالحة أو ترقية تصحيحية تحفظ الحركات والموافقات والاستحقاقات.

التدوير يبطل الرابط والتذكرة القديمة ولا يمحو الحركات أو يعيد استهلاكها. الإبطال لا يعيد السعة المصروفة. الخروج يعامل كخروج، ولا يرفض لمجرد نفاد حصة الدخول. اختبار هذه الثوابت موجود في مجموعات الدعوات والبوابة؛ قبول البطاقات المطبوعة والأجهزة متعددة البوابات يحتاج تجربة ميدانية.

## حدود offline

- التوليد المبدئي ليس قبول دخول، والتسجيل المحلي ليس QR نهائيًا.
- 401/403 من manifest يزيل البيان المخزن؛ لا يُسمح بالرجوع إليه بسبب انقطاع لاحق.
- البيان التالف أو الذي يخص فعالية أخرى يرفض ويزال بدل الرجوع لنسخة مخبأة.
- المنتهية مناوبته أو بيانه، أو ذو checkpoints=[]، لا يملك إذن دخول محليًا.
- heartbeat يبلغ التتبع فقط ولا يستطيع تغيير نطاق الجهاز أو مناوبته.
- لا توجد ضمانة لخمس أيام أو لحصة مشتركة عبر أجهزة مدارة معزولة. سلطة الخادم المتاحة شرط لذلك النمط.
