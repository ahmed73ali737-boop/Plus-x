## الاستخدام

- من الموقع: افتح `/start` أو رابط «التطبيق والدخول». اختر «الاستمرار كضيف» للتصفح والمشاركة، أو «تسجيل الدخول» للحساب القائم، أو «إنشاء طلب حساب جهة».
- إنشاء الحساب هنا طلب لمنظم أو جهة مشاركة، بمراجعة وصلاحيات لاحقة؛ ليس تسجيل حساب شخصي للزائر ولا إنشاء حساب مدير تلقائيًا. إنشاء فعالية أو صفحة يتم من الإدارة بعد اعتماد الحساب ومنح صلاحياته.
- تنزيل Android: `/downloads/pulsex-android-preview.apk`. يعرض `/api/downloads/android` الحجم والبصمة ونوع الإصدار. يُرفض الملف إذا غاب أو لم تتطابق بايتاته مع دليل البناء.
- يحتاج التطبيق إلى عنوان HTTPS لخادم المؤسسة عند أول استخدام. الموقع المنشور وعنوانه لم يردا في هذه الجلسة، لذلك لا يُدّعى أن الرابط أصبح متاحًا على خادم فعلي بمجرد تعديل الشفرة.

## الأمان

- تنزيل من مسار ثابت فقط؛ لا اختيار ملف أو إعادة توجيه إلى رابط تنزيل غير موثوق. Content-Disposition وMIME وnosniff محددة، وتخدم نسخة APK المتحقق منها.
- ملف المعاينة لا يخزن كلمة مرور في عنوان الخادم. مراجعة مصدر Android: HTTPS، رفض تجاوز SSL، إيقاف mixed content وfile/content access، وحصر التنقل/الصلاحيات بالأصل، وكاميرا اختيارية. توقيع الاختبار وWebView debugging في نسخة المعاينة يمنعان تسميتها إنتاجية.
- request signup لا يصدر جلسة أو حسابًا أو صلاحيات؛ اختبار SQL يثبت بقاء عدد المستخدمين ثابتًا. حد منفصل 10 طلبات/دقيقة لكل IP/عامل يحد الإغراق المحلي، ولا يساوي حماية موزعة أو اختبار اختراق.
- تحققات consent في النموذج، وتعطيل التكرار أثناء الإرسال، ورسالة واضحة عند عدم تأكيد الاستلام. لا وعد بإرسال SMS أو بريد آلي.
- لا تغيير في منطق حصص الدعوات أو سلطة الخادم أو الترحيلات. تظل الدعوات المدارة محتاجة للخادم عند المسح؛ التصفح المحلي لا يمنح قبول دخول.

## التحقق

نجح التنزيل الحقيقي عبر HTTP المضمن، وطابقت بصمته الملف 299736 بايت. نجحت حالات رفض الملف المفقود أو المتلاعب أو الحجم أو العقد المخالف، وHEAD، ومنع وصول غير مسجل إلى الإدارة. نجحت عقود خيارات الضيف والدخول وطلب الجهة وإلزام اختيار فعالية للمشاركة ومنع الاستدعاء المكرر.

أُضيفت رحلة Chromium للموقع والتنزيل وموافقة الطلب و390px ولقطات الهاتف/سطح المكتب إلى وظائف CI. محليًا تعذر تنزيل Chromium، فلم تُنتج لقطة ناجحة أو اعتماد بصري؛ تقرير العائق محفوظ. لا تنسب اختبارات CI القديمة للواجهة الجديدة.

كشف التشغيل العام الأول جمع اختبارات child-pytest من أدلة قديمة في codex-audit-artifacts، وليس خللًا بالتطبيق. أضيف pytest.ini يحدد `tests`؛ جميع اختبارات Python المتعقبة موجودة تحته. لم تحذف أدلة الفشل. كشف التشغيل التالي عقد API قديمًا لا يدرج endpoint الجديد؛ حُدث العقد وOpenAPI المولدة، ونجحت إعادته مع اختبارات التنزيل والواجهة. النتائج النهائية محفوظة مع دليل الرفع عند اكتمالها.
