# تسليم تعديلات الاختبارات المحلية — R01

تحتاج الخطة الأصلية إلى خمسة اختبارات معدلة وملف انحدار جديد خارج HEAD على جهاز Windows. أداة `tools/export_local_test_patch.py` تجمع المصدر المتاح فعليًا على ذلك الجهاز لمراجعته. إنشاء الحزمة أو نجاح التحقق منها لا يعني استرداد الملفات الأصلية أو نجاح اختباراتها؛ يظل R01 مفتوحًا حتى مراجعتها ودمجها وتشغيل CI على المرجع الناتج.

## جمع الملفات من نسخة العمل الأصلية

المتطلبات: Python 3.10 أو أحدث وGit. نزّل ملف الأداة وحده إلى مجلد مستقل، ثم وجّهه إلى نسخة العمل التي تحتوي التعديلات. يمكن تشغيله من خارج المشروع، ولا يحتاج حزم Python إضافية.

مثال PowerShell عند حفظ الأداة في Downloads، مع مسار المشروع الوارد في الخطة:

```powershell
python "$env:USERPROFILE\Downloads\export_local_test_patch.py" export --repo "D:\RTS\Mr. Nashwan\Plus-x" --output "$env:USERPROFILE\Downloads\PulseX-R01-Tests-$(Get-Date -Format yyyyMMdd-HHmmss).zip"
```

يعرض الأمر مسار ملف ZIP الناتج في Downloads. أرفق هذا الملف لاستكمال المراجعة. إذا كان مسار مشروعك مختلفًا، استخدم مساره الفعلي في `--repo`. عند حذف `--output` تستخدم الأداة `codex-audit-artifacts/phase01-handoff/` بشرط أن يكون متجاهلًا بالفعل؛ لهذا يستخدم المثال مخرجًا خارجيًا مناسبًا أيضًا لنسخة العمل القديمة، دون تعديل `.gitignore`.

لإعادة التحقق من سلامة الحزمة دون استخراج محتوياتها:

```powershell
python "$env:USERPROFILE\Downloads\export_local_test_patch.py" verify "D:\path\to\handoff.zip"
```

## ما الذي تحمله الحزمة؟

- هوية HEAD وشجرة Git وقائمة ملفات الاختبارات المتغيرة وحالتها.
- بايتات الملفات في HEAD والفهرس ونسخة العمل بصورة منفصلة، مع تمثيل الحذف والملفات الجديدة صراحة.
- بصمات SHA256 وGit blob للبايتات المحفوظة؛ تبقى اختلافات LF وCRLF ظاهرة.
- الملفات الجديدة المؤهلة من مصدر الاختبارات، مع حصر الملفات المستبعدة أو رفض الحالات التي تمنع تسليمًا موثوقًا.

الأداة للقراءة والجمع: لا تضيف ملفات إلى الفهرس، ولا تنفذ commit أو checkout أو reset أو مزامنة مع GitHub. ترفض الكتابة فوق حزمة موجودة، والتعارضات غير المحلولة، والمسارات غير الآمنة. لا تجمع قاعدة البيانات أو السجلات أو كامل المستودع. إن لم تجد تغييرات مؤهلة، تفشل برسالة واضحة بدل إنشاء حزمة نجاح فارغة.

## استلام الحزمة وإغلاق R01

1. تحقق من الحزمة وبصماتها، ثم راجع هويتها وعدد ملفاتها. العدد الفعلي قد يختلف عن ستة؛ لا يُفترض تطابقها مع الاختبارات المذكورة في الخطة.
2. قارن الحالات الثلاث وراجع الفرق مع خط الأساس `f53c206c0d113e6db9c11afab7569fbe868b5dd7` ومع أحدث `main`. افصل تغييرات المحتوى عن اختلاف نهاية السطر.
3. ادمج الاختبارات المعتمدة في طلب دمج قابل للمراجعة فوق أحدث مصدر، مع معالجة التداخلات دون إسقاط التعديلات.
4. شغّل بوابات CI على SHA الناتج واربط النتائج به. أرقام Windows160 وLinux158 التاريخية لا تتحول إلى دليل لهذا المصدر تلقائيًا.

سلامة ZIP تثبت اتساق البايتات مع سجلها، وليست توقيعًا يثبت هوية المرسل أو صحة منطق الاختبارات.
