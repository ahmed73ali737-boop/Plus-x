# وحدة إصدار الشهادات — التصميم المحسن وحالة التنفيذ

التاريخ: 2026-10-21. المصدر المرجعي عند بدء العمل: `60d873932b3da714ab84864c511ee8a6ea1b1cea`.

## قرار المنتج والمعمارية

تُضاف الشهادات إلى Eventna / Plus-x كوحدة أعمال مستقلة داخل التطبيق الحالي. تشارك الهوية والنطاق والصلاحيات والتدقيق والتخزين والاستيراد والإرسال حيث تتوافق عقودها. لا ننسخ وحدة الدعوات ولا نكتفي بتغيير المسميات، ولا نفرض خدمة مصغرة أو وسيط رسائل جديدًا قبل الحاجة التشغيلية. الدعوة تمنح حق حضور؛ الشهادة توثق منجزًا. إصدار شهادة لا يمنح دخولًا، والحضور لا يثبت اجتياز دورة تلقائيًا.

المحرك المشترك المستهدف هو `Template → Validated Data → Frozen Snapshot → Render → Deliver`، مع سياسة خاصة لكل نوع مستند. وجود قوالب مظهر للمواقع أو قوائم Excel لا يثبت وجود مصمم وثائق بالطبقات. يُستخرج مكوّن مشترك بعد اختبار التطابق الفعلي في مشاريع الدعوات والكروت، مع توثيق مصدره وإصداره واعتمادياته وترخيصه. لا نفترض نقل مكوّن لم يُفحص.

الأنواع المستهدفة: حضور، مشاركة، إتمام، اجتياز، تقدير، تطوع، متحدث، عارض أو جهة راعية. تُحدد صلاحية الجهة لإصدار كل نوع؛ الشهادات التنظيمية أو المهنية المقيدة تحتاج سياسة اعتماد خاصة. تكون الوحدة قابلة للتضمين في مساحة شخصية أو أعمال بحسب الصلاحيات والباقات، مع ربطها اختياريًا بفعالية/دورة. أول تطبيق هنا مرتبط بفعالية؛ الشهادات المستقلة والمساحات الشخصية متطلبات لاحقة.

## حالة الشفرة المضافة في هذه الدفعة

| القدرة | الحالة والأثر |
|---|---|
| قوالب نصية بطبقات X/Y وحجم ولون ومحاذاة واتجاه | منفذة في خدمة التحقق؛ واجهة مبسطة للنص والموضع والحجم |
| متغيرات عربية وإنجليزية | منفذة بقائمة مسموحة؛ تُرفض المتغيرات المجهولة |
| إصدارات قوالب ثابتة | إنشاء نسخة جديدة؛ تغيير القالب لا يغير شهادة قديمة |
| إصدار فردي | منفذ عبر واجهة الإدارة وAPI مع طلب مقاوم للتكرار |
| سجل الشهادات | منفذ؛ API بصفحات حتى 200، والواجهة تعرض آخر 100 |

| رابط استلام خاص | منفذ؛ token عشوائي 256 bit، تُخزن بصمته فقط، مع استبداله |
| معاينة قبل الإصدار | منفذة بعلامة «معاينة — غير صالحة» دون حفظ شهادة |
| بيانات وتصميم ثابتان بعد الإصدار | منفذة عبر حالات الاستخدام؛ لا يوجد endpoint لتعديلها |
| إلغاء بسبب وسجل تدقيق | منفذ؛ يبقى التحقق يعرض الحالة الملغاة، والتحميل يُمنع |
| انتهاء الصلاحية | تدعمه API والحساب عند القراءة؛ حقل واجهة الإدارة لاحق |
| SVG وPNG | SVG وPNG وPDF من الخادم؛ خط DejaVu عربي/لاتيني مرفق بترخيصه وبصمته |
| PDF من الخادم | منفذ كصورة عالية الدقة 300 DPI بخط عربي ثابت؛ ليس PDF نصيًا أو موقعًا رقميًا |
| صور الخلفية والشعار والتوقيع والختم | منفذة كصور PNG/JPEG محققة ومضمنة داخل نسخة التصميم، دون روابط خارجية |
| تحريك الطبقات | سحب ومفاتيح أسهم ومواضع رقمية متاحة؛ التراجع/الإعادة وترتيب الطبقات المتقدم ما زالا مطلوبين |
| Excel/CSV وربط أعمدة ومعاينة استيراد | منفذ للشهادات، مع أخطاء صفوف ومنع اعتماد المعاينة الخاطئة |
| إصدار مجمع/جدولة/عامل خلفي/طابور | منفذ بطابور قاعدة بيانات دائم؛ عامل محدود العناصر داخل دورة حياة التطبيق، ومعاملة مستقلة لكل عنصر |
| إرسال Email / WhatsApp / SMS | مطلوب؛ غير موصول، ولا تُعرض رسالة نجاح إرسال وهمية |
| «شهاداتي» وربط حساب المشارك | مطلوب؛ لا يُربط حساب تلقائيًا بمجرد تطابق اسم أو هاتف مستورد |
| مشاركة LinkedIn | رابط مشاركة للتحقق العام متاح؛ الإضافة إلى التراخيص تكامل مستقل |
| Apple Wallet / Google Wallet | مطلوب لاحقًا وفق إعداد المزوّد والتوقيع؛ ليس زرًا صوريًا |
| استبدال شهادة مصححة وربط السابقة بالجديدة | منفذ ذريًا؛ رقم جديد وسجل علاقة، وإلغاء السابق دون تغيير snapshot |
| أهلية من بيانات حضور/درجة | مطلوب؛ الإصدار الحالي اعتماد إداري يدوي للبيانات المدخلة |

هذه حالات تنفيذ في المصدر، وليست اعتماد نشر أو إثبات عمل قنوات خارجية. نتائج الاختبارات الفعلية موثقة في `docs/evidence/certificates/verification.txt` و`browser-result.json` عند توافرها.

## رحلة مدير النظام المستهدفة

1. الشهادات ← إنشاء برنامج إصدار: الجهة، نوع الشهادة، الفعالية/الدورة، اللغة، الصلاحية، سياسة إظهار البيانات.
2. اختيار قالب أو إنشاء نسخة منه. الفصل بين هوية المُصدر والجهة الراعية والتوقيع؛ لا يُعتمد توقيع لمستخدم بمجرد قدرته على رفع صورة.
3. تصميم الخلفية والطبقات: نص، صورة، QR، رقم شهادة، توقيع، ختم. محاذاة وشبكة وهوامش ومنطقة آمنة وقفل/إخفاء وترتيب وتراجع وإعادة؛ بديل رقمي ولوحة مفاتيح للسحب.
4. اختيار مصدر المشاركين: قائمة حالية، إضافة فردية، ملف، أو API موثوق. لا يُطلب حساب للمستلم ولا OTP إجباري.
5. ربط الأعمدة بالمتغيرات، وفحص البيانات والأهلية والمكررات. لا يكفي فحص تكرار الهاتف: الهوية الثابتة + المنجز + مستوى الشهادة تحدد التفرد، مع السماح لعدة أشخاص بوسيلة تواصل مشتركة وفق سياسة صريحة.
6. معاينة عينة تشمل أطول اسم، اسمًا عربيًا وإنجليزيًا مختلطًا، ودرجات/شروط مختلفة. المعاينة غير صالحة للإثبات.
7. مراجعة العدد والتكلفة والقنوات والموافقة والمرفقات والموعد. دعم فصل المُعد عن المعتمد في سياسة الجهة؛ لا نفرضه على الاستخدام البسيط.
8. اعتماد الإصدار. تثبيت نسخة القالب والخطوط والأصول والبيانات وقاعدة الأهلية والمُعتمد في snapshot. تُنشأ مهام التوليد والتوزيع بمعاملات واضحة.
9. مراقبة التقدم والنتائج الجزئية وإعادة المحاولة للفاشل فقط. عرض «أُصدر» مستقلًا عن «أُرسل» و«سُلّم» و«نُزّل».
10. التصحيح: تحديد السبب ← إلغاء/استبدال السابق ← إصدار جديد مرتبط به. لا يُعاد استخدام رقم الإصدار الملغى ولا يُحذف أثره.

في الواجهة المضافة حاليًا: اختيار فعالية ← الشهادات ← حفظ نسخة قالب ← معاينة بيانات المشارك ← إصدار ← فتح رابط الاستلام أو التحقق ← تحديث السجل أو الإلغاء.

## محرر القوالب والمخرجات

- القالب مستند JSON مهيكل ومحدد الإصدار، وليس HTML أو JavaScript حرًا. تُحل المتغيرات من schema ذي أنواع وحدود، وتُهرب النصوص قبل التصدير.
- التخطيط المستهدف بوحدات طباعة mm/pt مع تحويل عرض الشاشة؛ أحجام A4/A5 ومخصص، أفقي/عمودي، وملف تعريف طباعة. الوحدات الحالية بكسلية للنسخة الأولية.
- المتغيرات الأساسية: اسم المشارك، المعرّف الداخلي، اسم المنجز، الجهة، التاريخ، الرقم، الساعات، الدرجة، المستوى، فترة التدريب، انتهاء الصلاحية. حقول التواصل للتسليم فقط ولا تُطبع أو تُكشف بالتحقق افتراضيًا.
- الحقول المخصصة المستقبلية محددة النوع: نص/عدد/تاريخ/اختيار/رابط. منع تقييم تعبيرات المستخدم؛ الشروط مجموعة عمليات مسموحة مثل `grade >= 90`، دون `eval`.
- دعم RTL/LTR مستقل لكل طبقة، وتشكيل العربية واختلاط الأرقام والنص والتفاف/احتواء الأسماء الطويلة. لا يُصدر نص مبتور دون تنبيه أو منع حسب السياسة.
- الخطوط يجب أن تكون مرخصة ومضمنة ومثبتة الإصدار. اختيار Diwani/Kufi/Arial/Times لا يثبت توافر الملف أو حق تضمينه. البروفة النهائية تُنتج بنفس محرك التصدير والخطوط المستخدمة في الإصدار.
- صور التوقيع/الختم علامة بصرية؛ لا تعادل توقيعًا رقميًا مشفرًا. تُحدد حقوق استخدامها وتُحفظ بصمتها، ولا يُكشف أصل الصورة الشفافة للعامة.
- المخرجات المستهدفة PDF بخطوط مضمّنة وPNG/JPG، مع سياسة دقة وحجم وألوان. الأصول تُخزن بمفاتيح غير قابلة للاستبدال، والتوليد عند الطلب يُخزن مؤقتًا وفق snapshot hash + renderer version.
- يظل السجل هو الحقيقة. يمكن منع تحميل شهادة ملغاة من النظام، لكن لا يمكن سحب صورة سبق تنزيلها من جهاز المستلم؛ التحقق المباشر يكشف حالتها الحالية.

## دورة الحياة والتفرد

الحالة المستهدفة للمستند: Draft → Pending approval (اختياري) → Issued → Revoked أو Superseded. الانتهاء مشتق من الزمن ولا يعيد الكتابة على السجل. حالات التوليد والتوزيع منفصلة عن حالة الشهادة.

- بيانات المسودة قابلة للتعديل؛ الإصدار ثابت. تفويض مستخدم لتصميم القالب لا يمنحه تلقائيًا حق الإصدار أو الإلغاء.
- `Idempotency-Key`/مفتاح الطلب داخل نطاق الجهة والعملية: إعادة نفس البيانات تعيد النتيجة؛ إعادة المفتاح ببيانات مختلفة تعطي تعارضًا.
- قيد تفرد قاعدة البيانات يمنع نجاح إصدارين متزامنين لنفس المشارك والمنجز، ولا يعتمد على فحص الواجهة وحده.
- الإصدار الحالي يقفل التفرد على `event_id + recipient_key + award_key` ويشمل الملغاة. تعاد الشهادة المصححة مستقبلًا عبر عملية استبدال مرتبطة، لا التحايل بمفتاح عشوائي جديد لنفس المنجز.
- رقم الشهادة منفصل عن معرّف قاعدة البيانات وعن رابط الاستلام. لا يستخدم الهاتف في QR أو رابط عام.
- بصمة snapshot الحالية لا تعد توقيعًا رقميًا ولا تمنع مسؤول قاعدة بيانات يملك سلطة تعديل السجل والبصمة معًا. توقيع جهة مُصدرة بإدارة مفاتيح وتدوير وإبطال إضافة مستقلة عند الحاجة.

## الوصول والخصوصية والتحقق

| المسار | السياسة |
|---|---|
| الإدارة | جلسة + CSRF للكتابة + صلاحية الشهادات + نطاق الفعالية |
| الاستلام | رابط سري عشوائي؛ حامله يستطيع الوصول. يمكن تدويره دون تغيير رقم الشهادة |
| التحقق | رقم عشوائي أو QR؛ يعرض الاسم والمنجز والجهة وتاريخ الإصدار والحالة فقط |
| دليل عام للمشاركين | غير مسموح افتراضيًا؛ لا يوجد endpoint لسرد شهادات الجمهور |
| السجل الملغى/المنتهي | تظهر الحالة، ويمنع النظام تحميل النسخة الأصلية عبر رابط الاستلام |
| دون اتصال | يمكن الاحتفاظ بنسخة سبق تنزيلها؛ الحالة الحالية للإلغاء تحتاج اتصالًا بالخادم |

صفحات الشهادات لا تُخزن كبيانات في Service Worker؛ API تستخدم `no-store`. تطبق استجابات الخادم منع الفهرسة وno-referrer، وحدًا محليًا 300 طلب/دقيقة لكل IP لمسارات الشهادات العامة. مطلوب قبل الإنتاج حد موزع على مستوى البوابة يناسب الاستعمال، وعدم تسجيل token في سجلات الوكيل/التحليلات، وسياسة مدة الاحتفاظ وحذف بيانات التواصل. QR ليس مانع تزوير بمفرده: يجب مطابقة بيانات صفحة الجهة الموثوقة مع المستند المعروض. لا يثبت عنوان جهة أدخله المدير وحده اعتمادًا رسميًا خارجيًا.

## نموذج البيانات والتكامل

الموجود حاليًا:
- `px_certificate_templates`: الفعالية، اسم نسخة القالب، design، الإنشاء.
- `px_certificates`: الفعالية، نسخة القالب، مفاتيح الطلب والمشارك والمنجز، الرقم، بصمة رابط الوصول، snapshot وبصمته، الإصدار والانتهاء والإلغاء والسبب.
- تدقيق النظام الحالي يسجل إنشاء القالب والإصدار والإلغاء وتدوير رابط الاستلام؛ لا يسجل الرابط السري.
- migration إضافية `011_certificates.sql` مسجلة في فحص جاهزية PostgreSQL ولا تعدّل ترحيلات قديمة.

الجداول المستهدفة التالية: `certificate_programs`, `template_versions`, `asset_versions`, `issuance_drafts`, `eligibility_evidence`, `approval_decisions`, `issuance_batches`, `issuance_items`, `render_artifacts`, `delivery_jobs`, `delivery_attempts`, `transactional_outbox`, `certificate_account_links`, `certificate_replacements`.

كل سجل عمل يحمل نطاق الجهة/الفعالية عبر علاقات لا تثق بمعرف يرسله العميل. عامل الخلفية يعيد التحقق من النطاق وحالة الشهادة قبل التصدير/التسليم. ربط المشارك بحساب يتم عبر هوية سبق التحقق منها أو إجراء مطالبة مضبوط؛ عدم إلزام OTP بالتسجيل لا يبرر إلحاق شهادات حساب آخر.

## الاستيراد والإصدار المجمع والتوزيع المطلوب

الاستيراد مرحلتان: preview ثم commit بمعرّف محفوظ ومقيد بالمستخدم والنطاق ومدة الصلاحية وبصمة ملف/خريطة. رفض عناوين مكررة، قيم تواريخ/درجات غير صحيحة، ملفات مضغوطة تتجاوز الحدود، مكررات الهوية والمنجز. تسرد أخطاء الصفوف دون فقد بقية البيانات، ولا يسمح باستيراد جزئي صامت. CSV المصدّر محمي من spreadsheet formula injection.

التوليد والتوزيع يعملان عبر outbox يُكتب في معاملة الإصدار نفسها. تنفيذ at-least-once مع مفاتيح تفرد للإصدار والأثر الخارجي، قفل/lease للعامل، محاولات بتراجع وjitter وحدود، dead-letter وإعادة محاولة يدوية. يعرض تقدم الدفعة والفاشل وسبب الفشل، ويستأنف بعد إعادة التشغيل. إلغاء الدفعة يوقف العناصر التي لم تُصدر فقط؛ الملغاة لا تُمحى.

مواعيد الإرسال تحفظ UTC مع منطقة زمنية معلنة. يحدد المستخدم: إصدار الآن وإرسال لاحقًا، أو إصدار وإرسال عند الموعد. قبل الإرسال تُفحص حالة الشهادة وموافقة القناة وسياسة الجهة وحدود المزوّد.

البريد يتضمن نصًا بديلاً ومعاينة آمنة ورابط وصول، ومرفق PDF اختياري بحجم محدود. SMS/WhatsApp يتطلبان موصلًا معتمدًا وإعداداته وقوالبه وموافقاته. إشعار webhook يُتحقق من توقيعه ويُعالج بتفرد؛ «قبله المزوّد» لا يعني «سُلّم». فشل قناة لا يعيد إصدار الشهادة. روابط التتبع الخارجية لا تتضمن token دون ضرورة معلنة.

LinkedIn مشاركة رابط تحقق عام منفصلة عن إضافة سجل مؤهل؛ لا يُفترض نشر أو تعديل الملف تلقائيًا. المحافظ الرقمية تعتمد متطلبات الجهة المزوّدة والتوقيع والتحديث، ولا تتحول شهادة PDF إلى تصريح محفظة موثوق بمجرد تغيير الامتداد.

## معايير القبول والأدلة

الإغلاق الكامل يتطلب مصفوفة تغطية هذه البنود بأدلة، واختبار رحلات عبر الأدوار لا الاكتفاء بعدد الاختبارات. ترتيب الدفعات: النواة الحالية → محرر وأصول وخطوط وتصدير رسمي → استيراد وأهلية واعتماد ودفعات → قنوات وبوابة «شهاداتي» → محافظ وتوقيع واختبارات ميدانية. تبقى الدعوات والحضور والبطاقات الحالية ضمن اختبارات الانحدار في كل دفعة.

## التحقق المحلي لهذه الدفعة

## تحديث الدمج والتنفيذ الثاني — 2026-10-21

دُمج فرع التسجيل بالهاتف في مرشح الشهادات مع الحفاظ على حجب APK المبلغ عنه. احتفظ سجل الترحيلات بكلا الملفين 011 المختلفين بالاسم، وأضيف 012 للدفعات والاستبدالات؛ هوية الترحيل اسم الملف الكامل، فلا نعيد تسمية ترحيل سبق تشغيله.

الجديد: محرر صور ونصوص وتحريك باللمس/الأسهم، معاينة بنسخة قالب قائمة، مخرجات PNG/PDF من الخادم، خط عربي/لاتيني مرفق بترخيصه بعد تصغير نطاق محارفه، استيراد محدود من Excel/CSV مع mapping ومعاينة محفوظة، عامل دفعات دائم مع جدولة، وفحص صلاحية المُصدر مجددًا عند كل عنصر، وتصحيح ذري برقم جديد.

PDF الحالي صورة عالية الدقة؛ لا يدّعي بحث النص أو PDF/A أو توقيعًا رقميًا. تغيير ملف الخط يستدعي الحفاظ على الإصدار السابق؛ إذا اختلفت بصمة الخط يرفض التصدير الأصلي. عينة PDF العربية فُحصت بصريًا محليًا. لا توضع ملفات الأصول الشفافة الأصلية في مسار عام؛ تطبع نسخها داخل الشهادة التي يحق لحامل رابطها تحميلها.

مسارات إضافية: `download.png`, `download.pdf`, `certificates/import/preview`, `certificates/import/commit`, `certificates/batches`, و`certificates/{id}/replace`. جداول إضافية: `px_certificate_imports`, `px_certificate_jobs`, `px_certificate_replacements`. عند انقطاع عامل الإصدار تتراجع معاملة العنصر، ويستأنفه عامل آخر. لا تُخزن روابط الاستلام السرية في نتائج الدفعات؛ يُنشأ الرابط من الإدارة عند الحاجة. الجدولة تخص الإصدار، لا إرسال رسالة لمزوّد غير مُعد.

تبقى موصلات التسليم الخارجية والمحافظ الرقمية و«شهاداتي» الآمنة وربط الهوية والأهلية الآلية والموافقات متعددة المراحل والتراجع/الإعادة والتحسينات المتقدمة للمحرر بنودًا مفتوحة؛ لا يثبت الدمج اكتمالها.

التصدير الثقيل من الخادم محدود محليًا إلى 15 طلبًا في الدقيقة لكل IP، والتحقق/العرض إلى 300. قوائم السجل تعرض بيانات الشهادة دون نسخ صور القوالب لكل صف. يقترن العامل الخلفي بدورة حياة التطبيق؛ SQLite الذاكري ذي الاتصال الواحد في QA يستعمل المعالجة الصريحة دون خيط خلفي. للضغط الإنتاجي يلزم قياس الحمل وحد موزع وتخزين مخرجات خاص وفق البصمة.

أضيفت رحلة Chromium فعلية إلى guest-qr-ci لاختبار إنشاء قالب ومعاينة وإصدار وتنزيل PDF/PNG وواجهة جوال والإلغاء والتحقق. يتعذر تشغيلها محليًا بسبب تنزيل Chromium غير صالح، ولذلك لا يُدعى نجاحها قبل قراءة نتيجة CI. توسعت بوابة PostgreSQL المعزولة لتختبر ثمانية طلبات إصدار متزامنة: شهادة واحدة وسبع إعادات للنتيجة دون تكرار.

قبل الإصدار الفردي أو معالجة عنصر دفعة، تُقاس حدود النص بالخط المرفق ويُرفض النص الذي يخرج من مساحة الشهادة بدل قص الاسم بصمت. تستلزم معالجة الصفوف الفاشلة تصحيح البيانات أو القالب ثم إنشاء معاينة/دفعة مصححة؛ لا تعاد محاولة خطأ بيانات بلا تعديل.

التحقق المحلي بعد توحيد الهاتف والشهادات: **602 passed, 1 skipped, 14 subtests passed**. بعد آخر تقوية للتصدير ورفض تجاوز النصوص، نجحت 16 حالة مركزة تشمل الشهادات والترحيلات وPWA. ملف `integration-initial.txt` يحفظ الفشل الأول قبل إصلاح افتراض ترتيب الترحيلات؛ `merged-suite.txt` يحفظ إعادة التشغيل الناجحة. لا تستبدل هذه النتائج أدلة CI المطابقة للشفرة المرفوعة.
