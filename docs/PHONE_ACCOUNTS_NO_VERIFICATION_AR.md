# الحسابات برقم الهاتف — دون OTP أو تحقق

هذا المستند هو المرجع الحالي، ويستبدل مسار OTP التجريبي السابق حسب تأكيد المستخدم بتاريخ 20 أكتوبر 2026.

## رحلة المستخدم

1. يختار «إنشاء حساب برقم الهاتف».
2. يدخل الاسم ورقم الهاتف وكلمة المرور وتأكيدها.
3. يُنشأ الحساب وتبدأ جلسته مباشرة، وتفتح صفحة «حسابي»؛ لا رمز ولا رسالة تحقق ولا انتظار اعتماد لحسابه الشخصي.
4. لاحقًا يدخل برقم الهاتف وكلمة المرور، أو يتصفح كضيف دون حساب.
5. طلب إدارة جهة أو فعالية منفصل عن الحساب الشخصي ويحتاج اعتماد صاحب الصلاحية. لا يمنح التسجيل العام دور مدير.

تعمل الأرقام المحلية اليمنية وصيغ `+967` و`00967` والأرقام العربية. الصيغ المكافئة تشير إلى حساب واحد. الأرقام الدولية تحتاج رمز الدولة. كلمة المرور بين 12 و256 حرفًا، والتأكيد يجب أن يطابقها. لا تُضاف آلية OTP عبر إعداد بيئي قديم؛ مسارات طلب الرمز والتحقق منه محذوفة من التطبيق.

## الحسابات القائمة والإدارة

- يبقى دخول الحسابات القديمة بالبريد متاحًا، مع خيار واضح في واجهة الدخول، دون حذف الحسابات أو تغيير صلاحياتها.
- يستطيع صاحب حساب قديم ربط الهاتف بعد إدخال كلمة مروره الحالية، دون OTP. تنتهي الجلسات بعد الربط، ثم يدخل بالهاتف. لا يمكن الاستيلاء على رقم مرتبط بحساب آخر، أو استبدال رقم قائم من هذا المسار.
- إنشاء حسابات الجهات واللجان يدعم الهاتف. الحساب الإداري الجديد يُنشأ بكلمة عشوائية مؤقتة ويلزم تغييرها عند أول دخول.
- إسناد جهة أو لجنة إلى حساب شخصي موجود يربط الحساب نفسه؛ لا يبدّل كلمة مروره ولا يكرر المستخدم. الصلاحية تُمنح فقط بعد الإسناد الإداري.
- اعتمادات طلبات الجهات تُنفذ مرة واحدة. إعادة طلب الاعتماد لطلب سبق اعتماده أو رفضه ترجع 409 بدل إنشاء جهة أخرى.

## نسيان كلمة المرور

يعرض زر «نسيت كلمة المرور» تعليمات التواصل مع مسؤول المنصة أو الجهة. لا توجد خطوة تحقق أو OTP في واجهة المستخدم.

مدير المنصة يبحث عن الحساب برقم الهاتف من الإعدادات، ثم يصدر كلمة مرور مؤقتة تظهر مرة واحدة. ويمكن للمنظم إعادة تعيين كلمات مرور حسابات الفريق والجهات ضمن نطاقه فقط. بعد العملية تنتهي كل جلسات الحساب، وتُفرض كلمة جديدة عند أول دخول. الحساب الموقوف لا يُفعّل بالاستعادة. لا يُسمح بتغيير كلمة المرور لمجرد إدخال رقم هاتف من صفحة عامة.

مدير المنصة يستطيع كذلك إيقاف الحسابات الشخصية أو تفعيلها. الإيقاف ينهي الجلسات فورًا. أحداث الإنشاء والربط والاستعادة والإيقاف تسجل في التدقيق دون كلمات المرور.

## مصفوفة التنفيذ والأدلة

| المتطلب | الواجهة | API | قاعدة البيانات / الصلاحية | الاختبار |
|---|---|---|---|---|
| إنشاء مباشر بالهاتف | `/account/signup` | `POST /api/auth/register` | مستخدم attendee بلا نطاق إدارة؛ هاتف فريد | register/normalization/concurrent_registration |
| الدخول بالهاتف | `/admin` | `POST /api/auth/login` | نفس المستخدم والجلسات الحالية؛ الكلمة مطلوبة دائمًا | wrong_login/normalization/real_http |
| صفحة الحساب والتغيير | `/account` | `/api/auth/me`، `/api/auth/password` | الحساب الحالي فقط؛ إبطال الجلسات عند التغيير | self_password_change وDOM contracts |
| ربط حساب قديم بهاتف | `/account` | `POST /api/auth/phone` | جلسة + CSRF + كلمة حالية؛ دون تغيير الدور | legacy_account_adds_phone/phone_cannot_be_taken |
| طلب جهة بالهاتف | `/start#account` والنافذة العامة | `/api/signup-request` | pending دون منح صلاحيات | phone_only_business_request |
| إنشاء جهة/عضو/لجنة بالهاتف | إدارة المستخدمين والمؤسسات واللجان | المسارات القائمة مع phone | صلاحيات المؤسسة/الفعالية الحالية | operator/organization/committee tests |
| استعادة من الإدارة | الإعدادات أو إدارة المستخدمين | `/api/admin/users/{id}/password/reset` | منصة، أو منظم ضمن نطاقه؛ كلمة مؤقتة | administrator_recovery/operator_scope |
| إيقاف الحساب الشخصي | الإعدادات ← البحث بالهاتف | `PATCH /api/admin/users/{id}` | مدير المنصة فقط | platform_can_suspend_and_reactivate |
| إلغاء OTP | لا توجد شاشة رمز | لا مسارات request/verify | إعداد mock القديم لا يعيدها | no_otp_routes_even_with_old_mock_environment_flag |

## الترقية والتوافق

الترحيل `011_phone_accounts.sql` إضافي وقابل لإعادة التشغيل، وينشئ `px_user_phones` مع قيد فريد للرقم وللمستخدم، دون إعادة بناء جدول المستخدمين أو تعديل بريد الحسابات القديمة. قاعدة المستخدمين القديمة تتطلب قيمة فريدة في عمود email؛ للحسابات الهاتفية فقط تُستخدم قيمة داخلية محجوزة بصيغة `tel:+...`، وليست عنوان بريد. لا تعرضها واجهات الحسابات كبريد؛ تعرض الهاتف وemail=null.

أُلغي ترحيل OTP الخاص بالمسودة غير المنشورة. الترحيل 010 في main خاص بالإعدادات والإشعارات ويُحفظ كما هو؛ الترحيل 011 يضيف حسابات الهاتف. لا تُحذف بيانات أي جدول تاريخي موجود.

لا يُربط حساب مسجل حديثًا تلقائيًا ببطاقات ضيوف قديمة لمجرد تطابق الهاتف، ولا يُعاد إصدار بطاقة دعوة قديمة بمعرفة رقم الهاتف وحده. قواعد QR وسلطة الخادم على الدعوات والسعة لم تتغير.

## التحقق وحدوده

```sh
python -m pytest -q tests/test_phone_account_journey.py
node --experimental-vm-modules --test tests/phone_account_ui_contract.mjs
node tests/session_ui_contract.mjs
python tools/generate_openapi.py --check
python tests/browser_phone_accounts.py
```

الاختبارات المحلية تشمل SQL حقيقيًا على SQLite وطلب HTTP حقيقيًا إلى خادم منفصل، والتزامن، والصلاحيات، والترحيل، والحسابات القديمة. اختبارات DOM تختبر إرسال النموذج دون طلب تحقق، والتأكيد، ومنع الإرسال المكرر، وحدود حساب المستخدم.

اختبار Chromium الأصلي مضاف إلى CI على Windows وLinux. المحاولة المحلية توقفت عند بدء Chromium بسبب `socket() failed: Operation not permitted` قبل فتح الصفحة؛ لا تُعد دليل نجاح بصري. اختبارات PostgreSQL تستعمل مخططًا معزولًا جديدًا عند ضبط `PX_ACCOUNT_TEST_DATABASE_URL`؛ نتائجها الخارجية لم تثبت في هذه الجلسة. لا توجد عملية نشر أو تفعيل على الموقع الحي ضمن هذه النتيجة.

أدلة الإصدار الحالي في `qa/phone-accounts/`. أدلة `qa/account-otp/` تاريخية ومُلغاة كمرجع للسلوك الحالي.

نتيجة التحقق: 592 اختبارًا ناجحًا واختبار متجاوز قبل دمج main، و91 اختبارًا ناجحًا بعد دمج تحديث الإعدادات والإشعارات عند 65779a2. إرسال الإشعارات من الإدارة يدعم رقم الهاتف، وتبقى إعدادات المظهر وصندوق الإشعارات الخاص محفوظين للحسابات الجديدة.
