# التسليم الحي والنطاق والوكيل المشترك

## الحالة المثبتة

خط الأساس: main عند 8541dbc58d508bc7db32d4aa86399dd63ee8a818، ويشمل دمج #38 وإصلاحات #39 لهوية المصدر. نجحت فحوص main الستة المتاحة لهذا الرأس. لم تظهر مهمة APK جديدة ضمن النتائج المتاحة لهذا الرأس، فلا تُختلق له نتيجة بناء جديدة.

في 20 أكتوبر 2026 تعذر من بيئة الفحص الوصول إلى eventna.app: فشل حل الاسم محليًا، وانتهى اتصال الوكيل بالمهلة، وأرجعت أداة فحص التسليم ConnectError. طلب HTTPS إلى عنوان IP نفسه رفضته مطابقة اسم الشهادة؛ لم يُعطل التحقق من TLS. هذه ملاحظات اتصال من بيئة الفحص، ولا تثبت وحدها أن DNS العام أو التطبيق متعطل لدى الزوار. لا يوجد في هذه البيئة وصول SSH مُهيأ لهذا الخادم، ولم يُطبّق تعديل على DNS أو الوكيل أو قاعدة التشغيل.

## فحص مستقل من المصدر الذي تريد نشره

من checkout نظيف للرأس المستهدف، ومع بيئة QA المعتمدة المثبتة:

~~~bash
python tools/verify_live_delivery.py \
  --origin https://eventna.app \
  --expected-source "$(git rev-parse HEAD)" \
  --output qa/live-delivery.json
~~~

النتيجة تعيد exit code غير صفري عند فشل الوصول أو أي عقد مطلوب. الملفات تقرأ من checkout نفسه، ويقارن الفحص ما يلي:

- build في الصحة والجاهزية مع git-SHA الكامل، ومخطط PostgreSQL والترحيلات.
- جذر الموقع و/start و/admin، وملفات الواجهة وservice worker ببصمات المصدر، وmanifest وفهرس الضيوف.
- رفض GET الإدارة غير المصادق عليه بـ401.
- metadata وتنزيل APK الفعلي، الحجم وبصمة SHA256 المطابقة للملف المرجعي المحلي، ونوع المحتوى وattachment وnosniff.
- رفض التحويل إلى أصل آخر، والردود الكبيرة، والتنزيل الخارجي غير الموثق، ونسخة أقدم أو ملف واجهة قديم.

الفحص لا يرسل POST أو ينشئ حسابًا/دعوة/حضورًا، ولا يتبع redirects، ولا يضع كلمات مرور في تقاريره. HTTPS والتحقق من الشهادة إلزاميان. خيار --allow-local-test يقبل loopback فقط ويسجل local_test=true؛ لا يمثل ذلك تحققًا من الموقع العام. حتى النتيجة passed لا تُغلق قبول الإنتاج أو العتاد أو SLO أو RPO أو الأوفلاين الميداني.

## نطاق جذري بدل مسار فرعي

PulseX يستعمل /api و/assets و/downloads ومسارات PWA مطلقة. لذلك عنوان النشر العام يجب أن يكون مثل https://eventna.app/؛ مجرد إخفاء عنوان /eventna خلف تحويل DNS لا يعيد كتابة مسارات التطبيق. لا تغير PUBLIC_ORIGIN إلى عنوان به /eventna. أصلح مسار الوكيل عند النطاق نفسه أو نفذ مشروع دعم subpath مستقلًا إذا كان ذلك مطلوبًا لاحقًا.

## خادم به وكيل قائم

لا تشغّل وكيل Compose ثانيًا على 80/443 إذا كانت المنافذ مملوكة لوكيل الخادم. overlay في ops/compose.shared-edge.yaml:

- ينشر التطبيق على 127.0.0.1:14310 فقط، ويمكن تغيير PULSEX_HOST_PORT إلى منفذ محلي متاح.
- يترك PostgreSQL دون منفذ منشور.
- يجعل وكيل المشروع ضمن profile صريح dedicated-edge؛ التشغيل المقصود يستهدف app وتبعياته فقط.
- يحافظ على شروط الإنتاج والموافقات وإعدادات الأسرار الحالية.

قبل تغيير التشغيل، تحقق من اسم مشروع Compose الحالي وأسماء volumes ونسخة الاحتياط، واتبع دليل UPGRADE_PASSES_OFFLINE_RUNBOOK_AR.md. حافظ على اسم المشروع والملف البيئي الموجودين؛ تغيير اسم المشروع قد يفتح volumes جديدة ويبدو كأنه فقد بيانات. لا تستعمل down -v أو تعيد إنشاء الهوية أو تضع أعلام قبول صورية.

للمشغل المخول وبعد استيفاء بوابة الإنتاج، الأمر هو نفس أمر Compose الحالي مع إضافة overlay، والحفاظ على خيارات -p و--env-file الحالية:

~~~bash
export PULSEX_SOURCE_SHA="$(git rev-parse HEAD)"
docker compose -f compose.yaml -f ops/compose.shared-edge.yaml config --quiet
docker compose -f compose.yaml -f ops/compose.shared-edge.yaml up -d --build app
~~~

لا تنفذ المثال دون خيارات المشروع الحالية إن كان التشغيل يستخدمها. ملف ops/Caddyfile.shared-edge.example مثال site block للنطاق فقط؛ أضفه إلى إعداد الوكيل القائم بعد مراجعة التعارضات، ولا تستبدل ملفه كله. إذا كان الوكيل القائم Nginx، طبق ربط النطاق إلى المنفذ المحلي المكافئ دون تشغيل Caddy جديد على منافذه. يجب أن تكون شهادة TLS للنطاق نفسه. لا تعطّل فحص الشهادة داخل Android أو المتصفح.

بعد التشغيل: شغّل فحص التسليم، ثم رحلة المتصفح الفعلية واختبار جهاز Android/الكاميرا والتعافي المقبول ميدانيًا. إصدار APK الحالي معاينة بتوقيع اختبار، وحجمه 299736 بايت؛ لا تعتمده كتوقيع إنتاج أو تحديث متجر.

## أدلة التحقق

نجح محليًا 35 اختبارًا مركزًا مع تخطي فحص Compose بسبب غياب Docker. أضيف فحص Compose إلزامي في وظيفة التعافي على CI؛ يفشل إذا غاب Docker أو نُشر التطبيق خارج loopback أو تغيرت بوابات الإنتاج. تقارير الاتصال والاختبار محفوظة في docs/evidence/live-delivery-20261020/. لا تُحوّل نتيجة الاختبارات الاصطناعية إلى قبول حي للنطاق.
